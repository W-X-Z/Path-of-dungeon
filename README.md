# 마왕의 미궁 노선도 (Path of Dungeon)

Mini Metro 의 노선 편집에 던전 디펜스를 섞은 게임입니다.

플레이어는 미궁의 통로를 바꾸는 마왕입니다. 지도 가장자리에서 인간군이 들어오고,
주변에는 오크 초소·독 늪·기름방 같은 방이 무작위 위치에 나타납니다.
**선을 잡아 방 위로 끌어다 놓으면 침입자가 그 방을 그 순서로 지나갑니다.**

수집하는 게임이 아닙니다. 가진 방들이 **제때, 제 순서로** 작동하도록 미궁을 설계하는 게임입니다.

```bash
npm start         # http://localhost:5173 (의존성 없음)
npm test          # 규칙 검증 27개
npm run balance   # 밸런스 하니스 — 아래 참고
npm run build     # dist/path-of-dungeon.html 단일 파일 (폰트까지 포함)
npm run fonts     # 폰트 서브셋 다시 만들기 (문구를 바꿨을 때만)
```

`?seed=123` 을 붙이면 같은 지도를 다시 불러옵니다. 전투가 결정론이라 시드 하나로
남이 겪은 상황을 그대로 재현할 수 있습니다.

---

## 설계의 중심: 거리에 의미를 주는 것

이 장르의 가장 흔한 함정은 **선을 그리는 행동이 전투 결과와 연결되지 않는 것**입니다.

침입자가 모두 같은 속도로 같은 길을 간다면, 길을 늘려도 서로의 간격은 변하지 않습니다.
쿨타임 6초인 방에 0초와 4초에 도착하는 두 부대는, 길을 늘려 3초와 7초에 도착해도 결과가 같습니다.
이러면 "선을 그린다"는 핵심 동사가 장식이 됩니다.

그래서 거리를 결과에 **직접** 묶었습니다.

| 장치 | 거리와의 관계 | 플레이어가 느끼는 압력 |
|---|---|---|
| 기름방 → 화염 제단 | 기름은 4초 뒤 마릅니다. 멀면 연계가 무산됩니다 | **붙여라** |
| 독 늪 → 다음 방 | 이동하는 내내 독이 누적됩니다 | **떼어놔라** |
| 거미굴의 둔화 | 파티 속도를 낮춰 하류 도착 시각을 밀어냅니다 | **타이밍을 밀어라** |
| 공유 방의 쿨타임 | 두 노선의 도착 간격이 곧 쿨타임 경쟁입니다 | **몰까, 나눌까** |

"붙여라"와 "떼어라"가 동시에 작용하므로 한 배치가 항상 정답이 되지 않습니다.
이 성질은 말로만 두지 않고 테스트로 고정했습니다 (`tests/sim.test.js`).

```
ok - 기름방과 화염 제단은 가까이 붙여야 연계가 성립한다
ok - 독 늪은 다음 목적지에서 멀수록 총 피해가 커진다
ok - 거미굴의 둔화는 하류 도착 시각을 실제로 밀어낸다
ok - 두 노선이 같은 방을 쓰면 쿨타임도 공유한다
```

## 전투 중에도 길을 고칩니다

배치하고 시작 버튼을 누른 뒤 지켜보기만 하는 시간이 길면 '하는 게임'이 아니라
'보는 게임'이 됩니다. 그래서 배치 단계와 전투 중이 같은 조작을 씁니다.
스페이스바로 멈추고, 선을 다시 긋고, 이어서 봅니다.

다만 규칙이 하나 필요합니다.

> **이미 출발한 부대는 출발 당시의 경로를 끝까지 유지합니다.**

이게 없으면 길을 계속 바꿔 적을 무한히 왕복시키는 수가 생깁니다.
경로는 한 번 굳히지 않고 **부대가 출발하는 순간에 그 부대 몫으로** 찍어 둡니다.
그래서 수정은 언제나 다음에 오는 부대에만 적용되고, 지금 화면에서 걸어가는 부대는
이미 사라진 방을 향해 계속 걸어갑니다. 통로 예산도 전투 중에 똑같이 적용됩니다.

이 두 가지 — 이동 중 부대의 경로 유지, 전투 중 예산 —를 테스트로 고정했습니다.

## 손맛

같은 피해라도 화면이 멈칫하고 흔들리고 숫자가 튀어나오면 체감이 완전히 달라집니다.
연출 계층(`src/render/juice.js`)은 규칙 하나만 지킵니다 —
**연출의 크기는 항상 실제 성과에 비례합니다.** 아무것도 아닌 일에 큰 연출을 붙이면
정말 큰일이 일어났을 때 쓸 카드가 남지 않습니다.

| 장치 | 언제 | 왜 |
|---|---|---|
| 타격 정지 | 처치 0.045초 · 연계 0.075초 · 동시 처치 0.1초 | 멈칫하는 한 프레임이 타격감의 절반입니다 |
| 화면 흔들림 | 피해량에 비례, 제곱 감쇠 | 제곱을 쓰면 잔챙이는 조용하고 큰 것만 크게 옵니다 |
| 피해 숫자 | 등장할 때 1.75배로 튀었다가 제자리 | 튀지 않는 숫자는 눈에 들어오지 않습니다 |
| **연계 호** | 기름방과 화염 제단을 잇는 불빛 | 내 설계가 맞물렸다는 것을 선으로 직접 보여 줍니다 |
| 연쇄 표시 | 1.5초 안에 이어진 처치 | 3연쇄부터 표시, 6연쇄에서 색이 바뀝니다 |
| 영혼 회수 | 처치한 자리에서 마왕성으로 빨려 들어감 | 처치가 곧 마왕의 이득이라는 인상 |
| 음높이 상승 | 연쇄가 길어질수록 5음 음계를 타고 올라감 | 화면을 보지 않아도 잘 되고 있다는 것을 압니다 |

## 아트

외부 에셋 팩을 섞지 않았습니다. 출처가 다른 그림을 모으면 크기·선 굵기·원근이
제각각이라 오히려 조잡해집니다. 모든 그림은 `src/art/sprites.js` 에 경로 데이터로
직접 작성했고, 캔버스와 패널이 **같은 데이터**를 씁니다.

방향은 **고서(古書)의 배선도** 입니다. Mini Metro 의 구조적 명료함을 유지하되,
흔한 청흑색 대시보드 대신 그을음 같은 따뜻한 먹색과 뼈흰색을 씁니다.
채도 높은 색은 '지금 무슨 일이 일어나는가'에만 쓰고 장식에는 쓰지 않습니다.

타이포는 바탕체 디스플레이(Gowun Batang) · 고딕 UI(Gothic A1) · 콘덴스드 숫자(Bebas Neue)
세 가지이고, **자체 호스팅**합니다. 외부 CDN 에 기대면 네트워크가 막힌 환경에서
타이포가 통째로 무너지고 단일 파일 빌드도 자기완결적이지 않게 됩니다.
소스에 실제로 등장하는 글자만 서브셋해서 5종 합계 250KB 안쪽입니다 (`npm run fonts`).

`tools/sprite-preview.html` 로 모든 스프라이트를 여러 크기로 한눈에 볼 수 있습니다.
경로 데이터는 그려보지 않으면 판단할 수 없습니다 — 실제로 이 페이지가
"오크 초소가 그냥 X 로 읽힌다", "기름방과 화염 제단이 작은 크기에서 구별되지 않는다"를
잡아냈습니다.

## 읽지 않아도 되는 화면

설명문을 늘리면 플레이어는 읽지 않고, 읽더라도 지도에서 눈을 뗍니다.
그래서 규칙 설명은 전부 **지도 위**로 옮기고 패널에는 지금 결정에 필요한 것만 남겼습니다.

- 배치 단계에 **연계 예측선**이 그려집니다. `연계 성립 3.2s` / `4.9s — 기름이 4.0s 에 마릅니다`.
  전투가 끝난 뒤에야 "기름이 말랐다"를 아는 것은 너무 늦습니다.
- 독 늪에는 `이동 중 46 피해 (최대 49)` 가 붙습니다. 떼어놓을 이유가 숫자로 보입니다.
- 공유 중인 방은 노란 점선과 `×2`. 쿨타임을 나눠 쓴다는 뜻입니다.
- 방 이름은 내 노선 위이거나 마우스를 올렸을 때만 나옵니다. 항상 켜두면 지도가 글자로 덮입니다.
- 조작 안내는 패널에 상주하지 않고 첫 판에 한 번만 나옵니다.
- **노려볼 만한 연계** — 이 지도에서 아직 만들지 않은, 실제로 성립 가능한 조합만 짚어 줍니다.
  읽을거리가 아니라 다음에 할 일입니다.

예측은 실제 전투와 일치해야 합니다. 어긋나면 UI 가 거짓말을 하는 셈이라
그 일치를 테스트로 고정했습니다.

## 규칙

**방**
- 침입자가 들어오면 자동 발동하고 쿨타임이 시작됩니다.
- 쿨타임 중에 들어온 침입자는 **그냥 통과합니다.**
- 여러 노선이 같은 방을 쓰면 **쿨타임도 공유합니다.** 이것이 Mini Metro 의 '혼잡한 역'에 대응합니다.
- 방에서 받은 상태효과는 다음 방으로 이동하는 동안에도 계속 흐릅니다.

**노선**
- 모든 노선은 마왕성에서 끝나야 하고, 한 노선이 같은 방을 두 번 방문할 수 없습니다.
- 전체 연결 거리에 예산이 있습니다. 여러 노선이 겹치는 구간은 **한 번만** 계산합니다 —
  공유가 싸야 "몰까, 나눌까"가 진짜 선택이 됩니다.
- 이동 중인 부대는 출발 당시의 경로를 유지합니다. 전투 중 길을 바꿔 적을 왕복시킬 수 없습니다.

**침입자**
- 종류가 아니라 **역할** 3개로 시작합니다. 기사(방어력) · 사제(회복) · 도적(속도·훼손).
- 파티는 함께 이동하되 체력은 개별입니다.
- 마왕성 피해는 **남은 체력에 비례합니다.** 죽이지 못한 피해도 값어치를 가져야
  플레이어가 개선을 체감할 수 있습니다.
- 상성은 완전 면역이 아니라 피해 감소·발동 지연입니다. 대응할 여지를 남깁니다.

## 실패를 이해하게 만드는 것

방을 하나 더 만드는 것보다 중요하게 다뤘습니다.
전투가 끝나면 결과가 아니라 **원인**이 나옵니다.

> **폭발 함정이 쿨타임이라 3번 그냥 통과당했습니다.**
> 가장 큰 손실은 12.4초에 기사×3을 놓친 것입니다 (남은 쿨타임 4.2초).
> → 이 방을 두 노선이 함께 쓰고 있다면 한쪽을 다른 방으로 돌리거나,
>   거미굴로 한쪽 도착을 늦춰 간격을 벌리세요.

> **기름 연계가 2번 무산됐습니다.**
> 기름방에서 화염 제단까지 평균 6.3초가 걸렸습니다. 기름은 4초면 마릅니다.
> → 두 방을 더 가깝게 잇거나, 사이에 낀 다른 방을 빼세요.

"화력이 부족했다"가 아니라 "폭발을 선발대에 써버렸다"를 읽어야 다음 노선을 고민하게 됩니다.
이 정보는 개발자에게도 밸런스 조정의 근거가 됩니다.

## 밸런스 하니스

전투는 **시드 기반 결정론**입니다. 같은 (지도, 노선, 습격, 시드) 는 항상 같은 결과를 냅니다.
덕분에 규칙을 바꾼 뒤 기존 빌드가 어떻게 달라졌는지 반복 확인할 수 있습니다.

`npm run balance` 는 탐욕적 플래너가 한 수씩 바꿔보며 최선을 찾아 전 판을 대신 플레이합니다.
사람의 최적 플레이는 아니지만 **성실한 플레이어의 하한선** 역할을 합니다.

```
시드 40판 (탐욕적 플래너)

  승리 37 (93%)   패배 3 (8%)
  승리 시 남은 마왕성 체력 중앙값 86

  습격별 마왕성 손실 (중앙값 / 최대):
    습격 3: 0.0 / 48.7
    습격 4: 4.4 / 54.1
    습격 6: 0.0 / 84.9
```

중앙값 0 과 최댓값 80 이 함께 나오는 것이 중요합니다. 잘 두면 막고 잘못 두면 무너진다는 뜻입니다.
중앙값과 최댓값이 같이 붙어 있으면 그것은 난이도가 아니라 세금입니다.

같은 배치를 자동으로 반복하기 때문에 수치를 감으로 정하지 않아도 됩니다.
실제로 이 도구가 두 가지를 잡아냈습니다.

- **습격 3의 손실이 정확히 30.0 으로 고정**돼 있었습니다. 플레이와 무관한 세금이라는 뜻입니다.
  원인은 도적의 함정 훼손이 쿨타임 검사보다 **먼저** 실행돼, 멀쩡한 방을 그 자리에서
  무효화시킨 것이었습니다 (도적 3명이면 71%). 훼손을 발동 **이후**로 옮겨
  "이번 발동은 되지만 다음이 늦어진다"로 바꿨습니다.
- 지도 생성이 방 종류를 매번 독립적으로 뽑아 **폭발 함정만 세 개인 지도**가 나왔습니다.
  봉지에서 뽑는 방식으로 모든 종류가 최소 한 번씩 나오도록 보장합니다.
- **기름 연계가 성립하는 방 쌍이 지도에 거의 생기지 않았습니다.** 기름은 4초면 마르고
  기사 속도로는 176유닛이 한계인데, 방을 무작위로 뿌리면 그 안에 두 방이 들어오는 일이
  드뭅니다. 이 게임의 핵심 연계가 지도 운에 좌우되고 있었습니다. 이제 성립 가능한 쌍이
  최소 하나는 있도록, 그것도 **첫 입구에서 손이 닿는 자리**에 놓습니다.
  핵심 재미를 몇 판 지나서야 처음 보게 만들면 안 됩니다.

## 구조

```
src/
  core/     rng(시드 난수) · geom · state(런 진행)
  data/     rooms · statuses · enemies · waves · rewards   ← 대부분의 튜닝은 여기서 끝납니다
  sim/      mapgen · graph(노선/예산) · battle(결정론 전투) · report(원인 분석)
  render/   canvas · theme · effects · hud
  input/    dragline(선 끌기)
  audio/    sfx(WebAudio 합성, 외부 파일 없음)
tools/      serve · bundle(단일 파일 빌드) · balance(밸런스 하니스)
tests/      규칙 검증
```

렌더링·입력·시뮬레이션이 분리돼 있어 전투 로직은 DOM 없이 Node 에서 그대로 돌아갑니다.
테스트와 밸런스 하니스가 실제 게임과 **같은 코드**를 쓰는 이유입니다.

방은 전용 코드 없이 **발동 조건 · 대상 · 효과**의 공통 구조로 선언합니다.

```js
oil_room: {
  name: '기름방', shape: 'diamond', cooldown: 2.5, target: 'all',
  effects: [{ type: 'status', status: 'oily', dur: 4.0 }],
  geometry: '화염 계열 방에 바짝 붙이세요. 4초 안에 도착하지 못하면 연계가 무산됩니다.',
}
```

새 방을 추가할 때 `src/data/rooms.js` 의 표만 늘리면 됩니다.

확장은 **새 예외 규칙**보다 **기존 규칙의 새 조합** 쪽이 유지 비용이 쌉니다.

| 방향 | 유지 비용 |
|---|---|
| 기존 방의 개조 선택 (같은 방으로 다른 빌드) | 낮음 — 아트 재사용 |
| 침입대 편성·출발 간격 추가 | 낮음 — 적 역할 재사용 |
| 입구 위치·예산·배치 조건 변경 | 낮음 — 노선 설계 자체가 새로워짐 |
| 새 상태효과 계열 | 중간 — 표시·저항·중첩이 전 콘텐츠에 영향 |
| 매번 고유 규칙을 가진 특수 방 | 높음 — 추가할수록 다음 콘텐츠도 비싸짐 |

먼저 검증할 것은 여전히 이 세 가지입니다.

1. 같은 방을 가지고 연결 순서만 바꿔도 결과가 의미 있게 달라지는가?
2. 침입대 구성이 바뀌면 기존 노선을 수정할 이유가 생기는가?
3. 실패한 플레이어가 원인을 설명하고 다음 시도에서 개선할 수 있는가?

---

## 조작

- **선 끌기** — 노선을 잡아 방 위로 놓으면 그 자리에 끼어듭니다.
- **방 누르기** — 선택된 노선에 넣거나 뺍니다.
- **스페이스바** — 전투를 멈추고 이어갑니다. 멈춘 동안에도 길을 고칠 수 있습니다.
- **노란 점선 테두리** — 여러 노선이 공유 중인 방. 쿨타임도 함께 씁니다.
- **빨간 링** — 쿨타임 진행 중. 지금 들어온 침입자는 그냥 지나갑니다.

마우스와 터치 모두 동작합니다.
